# 检验与返工

## 用途
第 6 步：用脚本检验输出文件，找出是哪一步出的问题，改进提示词后只重做那一步。

## 适用条件
- 第 3、4、5 步各自结束后用 `--stage table / analysis / final` 做阶段检验（发现问题早返工）。
- 第 6 步做最终检验：`--stage final`。

## 规则

### 检验命令
`python -X utf8 scripts/check_excel.py --work <work> --stage final`
- exit 0：没有 error，可以交付（warn 写进最终报告）。
- exit 1：读 `issues`，每条都有 `step`（出问题的步骤）、`check`（哪项检查）、`detail`（具体位置）。

### 问题 → 返工步骤
| check | step | 返工做法 |
|---|---|---|
| 榜单为空 / 榜单商品没有筛选结论 | 1 | 重跑 get_bs_list.py 或补全 filter.json 第 1 轮 |
| 筛选未完成 / 已剔除的商品出现在表里 | 2 | 补完第 2 轮筛选，跑 apply_filter.py --round 2，再重跑 build_excel.py |
| 保留商品未抓取 / 抓取失败 / 部分图片下载失败 / 没有主图 / product.json 被手改 | 2 | 只对这些 ASIN 重派抓取子代理（被手改的必须用 scrape_product.py 重抓，不能改回） |
| 缺少输出文件 / 缺少工作表 / 文件无法解析 / 图片没有嵌入单元格 / 图片比例被改变 / 显示框比例被改变 / A+图片数量不对 / 保留商品没有出现在表里 / 剔除记录与筛选结果不一致 / 文字被截断 | 3 | 重派制表子代理（文字被截断时先确认用的是最新版 build_excel.py，不要手改行高） |
| 图片分析为空 / 分析条数和图片数不一致 / 分析顺序或格式不对 / 分析像套模板 / 分析缺少图上文字 / 分析与图片不符 | 4 | 只对涉及的 ASIN 重派分析子代理，然后重跑 build_excel.py |
| 方案行数太少 / 方案字段为空 / 载体命名不对 / 方案缺少参考图 / 方案缺少参考链接 / 没有 plan.json / 方案没有体现新品卖点(warn) | 5 | 重派方案子代理，然后重跑 build_excel.py |

一次检验同时有多个步骤的问题：**先修最早的步骤**，修完重跑一次检验再看后面的（前面的问题经常连带后面的）。

### 返工提示词：必须写明问题
重派子代理时，在原提示词后面加一段“返工说明”，不能只说“重做”。写清四件事：
1. **上次做了什么**：原提示词的要点。
2. **哪里不合格**：照抄 `check` 和 `detail`。
3. **为什么会这样**：主代理自己判断的原因（例如“子代理没有打开图片，只根据标题写”“漏了 index 8 以后的图”“把 A+ 图也算进去了”）。
4. **这次怎么做**：具体改法，以及完成后要自查的点。

### 次数上限
- 每个步骤最多返工 **2 次**。
- 2 次后仍不合格：停止，向用户报告剩余问题（哪个步骤、哪些 ASIN、原因、已经试过什么），把当前文件照常交付并在报告里标明不合格项。
- 抓取类问题（亚马逊拦截）返工 2 次仍失败，属于正常结束：表里保留“【抓取失败】”行，在报告里列出这些 ASIN。

## 示例：返工说明
```
【返工说明（第 1 次）】
上次任务：分析 B0AAA、B0BBB、B0CCC、B0DDD、B0EEE 的主图和副图。
检验结果：
- 分析条数和图片数不一致：B0BBB 6 条 / 9 张
- 分析像套模板：“强调产品品质，提升购买信心”出现在 B0AAA、B0CCC、B0EEE
原因判断：B0BBB 只看了前 6 张图；另外 3 个商品的部分说明没有描述图上真实内容。
这次要求：
1. B0BBB：按 product.json 的 main_images 全部 9 张逐张 Read，重写整个文件。
2. B0AAA、B0CCC、B0EEE：重新打开对应图片，把上面那句套话换成图上具体的文字和画面元素。
3. 写完自查：每个文件 images 条数 = 有 thumb 的主图张数；没有两条说明完全相同。
```

## 特殊情况
- **检验脚本本身报错**（不是 issues，而是 Python 异常）：先修脚本或环境问题，不算返工次数。
- **用户在中途改了要求**（例如新增卖点）：从受影响的最早步骤开始重做，不算返工次数。
- **warn 级别问题**：不强制返工，写进最终报告让用户决定。

## 输出格式
最终报告（直接回复用户）包含：
- 两个文件的路径和大小；
- 类目、榜单前 N、保留 / 剔除 / 失败数量；
- 剔除名单在“剔除记录”表里（报告里只给数量和几个典型原因）；
- 失败的 ASIN 和原因；
- 没有问用户、自行判定的筛选结论（`filter.json` 里 `reason` 以“自行判定：”开头的）逐条列出，请用户核对；
- 返工记录（哪一步、几次、改了什么）和仍未解决的问题。
