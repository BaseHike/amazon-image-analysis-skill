# 新品视觉方案

## 用途
根据竞品图片的规律和用户新品的卖点，规划新品主图和副图每一张要表达什么，写进“新品视觉方案”表。

## 适用条件
第 5 步，第 4 步的分析全部完成、`summarize_analysis.py` 已生成 `stats.json` 之后。只规划主图和副图，不规划 A+。

## 规则

### 输入（子代理必须全部读）
- `job.json`：`product_name`、`selling_points`（新品卖点，方案的核心）。
- `stats.json`：每个图位竞品最常用的图片类型、各类型覆盖率、`gallery_size.median`、每种类型的示例图。
- `analysis/*.json`：竞品每张图的具体表达，用来找参考图。

### 张数
方案行数 = `stats.json` 里 `gallery_size.median` 四舍五入，最少 5 行，最多 9 行。第 1 行是主图。

### 每一行写什么
| 字段 | 写法 |
|---|---|
| 载体 | 第 1 行写“主图”，之后按顺序写“副图N｜主题”（N 从 1 连续编号，用“副图”不用“辅图”，和图片分类总表的列名一致），主题 2～6 个字，如“副图1｜配方结构”。`check_excel.py` 会检查这个格式 |
| 画面任务 | 这张图要让买家**看懂什么**，一句话，动词开头，如“把 7 Forms 从口号变成可读的配方地图” |
| 用户需求触发 | 买家**为什么需要看到这张图**：他心里的疑问或顾虑，如“用户想知道 7 种形态具体是什么、为什么不是单一成分” |
| 参考图 | 选一张竞品图：`{"asin": "...", "position": "主图/副图N/A+图N"}`，必须是分析里真实存在的图 |

### 只写表达，不写设计
- 不写配色、字体、版式、拍摄角度、构图比例、素材来源。
- 不写具体文案，写“要传达的意思”。
- 好：“让买家一眼确认是 7 种形态的复合镁，而不是普通单一镁”
- 差：“深蓝渐变背景，左侧放瓶子，右侧 3 行白色粗体字”

### 怎么排顺序
1. 主图：产品识别 + 最大差异点（新品卖点里最能区分竞品的那一个）。
2. 前 3 张副图：优先放**竞品覆盖率高**的类型（`type_coverage` 里 share ≥ 0.5 的），因为这是买家在这个类目默认要看的信息，同时用新品卖点去讲。
3. 后面几张：放新品独有的卖点，以及竞品普遍缺失但买家会关心的信息（覆盖率低但分析里出现过、且和卖点相关的类型）。
4. 最后一张：收口，回答“为什么现在买/为什么选我”（信任背书、规格汇总、售后保障之类）。
5. 每个卖点至少出现在一行的画面任务或用户需求触发里。

### 参考图怎么选
- 优先选**同一类型里排名最靠前**的竞品图（`stats.json` 的 `examples` 已按排名排序）。
- 参考的是“表达方式”，在用户需求触发里不用解释为什么选这张。

## 示例（新品：示例复合镁，卖点：7 种镁形态、睡眠放松、肌肉恢复）
`plan.json`：
```json
{
  "product": "示例复合镁",
  "rows": [
    {"carrier": "主图", "task": "第一眼确认产品是什么、规格是什么、和普通镁有什么不同",
     "trigger": "用户需要快速判断这是多形态复合镁，而不是普通单一镁",
     "ref": {"asin": "B0CRY2SVPV", "position": "主图"}},
    {"carrier": "副图1｜配方结构", "task": "把“7 Forms”从口号变成可读的完整配方地图",
     "trigger": "用户想知道 7 种形态具体是什么、为什么不是单一成分",
     "ref": {"asin": "B08WPLW4VN", "position": "副图1"}},
    {"carrier": "副图2｜睡前场景", "task": "把睡眠利益点转成可感知的夜间补充习惯",
     "trigger": "用户真实需求是睡前放松和建立规律，而不是被承诺“治疗失眠”",
     "ref": {"asin": "B08WPLW4VN", "position": "副图3"}}
  ]
}
```

## 子代理提示词模板
```
你负责为新品规划主图和副图的视觉方案。不要做其他事。

工作目录：<work>
规则：先完整读一遍 <SKILL_DIR>/references/visual-plan.md 并严格照做。
需要读的文件：<work>/job.json、<work>/stats.json、<work>/analysis/ 下全部文件。

用 Write 写入 <work>/plan.json（格式见参考文件示例）。
最后只回复 JSON：{"rows": 行数, "selling_points_covered": {"卖点": "第几行"}, "notes": "..."}
```

## 特殊情况
- **新品卖点和类目常见类型冲突**（如卖点是“无添加”，但竞品都在讲功效）：卖点优先，在用户需求触发里写清楚买家为什么在意这一点。
- **某个卖点竞品里完全没有参考图**：参考图选表达方式最接近的一张（例如同为“成分材质”类型），不要空着。
- **卖点超过方案行数**：合并相近的卖点到同一行，不增加行数。
- **卖点涉及医疗功效**（治疗、治愈）：画面任务改写成“支持、帮助”的说法，并在 notes 里提醒用户合规风险。

## 输出格式
`<work>/plan.json`：`{"product": "...", "rows": [{"carrier", "task", "trigger", "ref": {"asin", "position"}}]}`。
参考链接和参考图由 `build_excel.py` 根据 `ref` 自动填。
